# FinCore v0.2

This document collects the changes to the v0.1 specification
(fincore_language_specification_v0_1.md). The binding decisions are
numbered in docs/semantics_decisions.md ("v0.2 additions": 58–61 std, 62–71 formatTo, 72–85 sum types; the std API is in docs/stdlib.md); the
runtime side is in docs/runtime_api.md.

## Language additions in v0.2

### `formatTo`: finitist, compile-time-checked formatting

```go
func formatTo(dst []byte, format string, args...) usize
```

`formatTo` writes the formatted text into `dst`, starting at index 0. It
truncates silently at `len(dst)` and returns the number of bytes written,
which is always `<= len(dst)`. The written bytes are always a prefix of the
untruncated output. The function is Total: it never allocates and never
panics. A buffer, a constant format and a byte count are all it needs, so
it fits the fixed-arena style of `compiler/`:

```go
var b [64]byte
n := formatTo(b[:], "mismatched types %v and %v", x.typ, y.typ)
return io.WriteStdout(b[:n])
```

The format must be a constant string. It is parsed and checked against the
arguments at compile time. Each call is then expanded into straight-line
calls on the runtime writer `fincrt.Fmt`, with no format parsing and no
reflection at run time.

#### Directives

```
Directive = "%" { "-" | "0" } [ Width ] Verb | "%%" .
Width     = decimal_digit { decimal_digit } .   // 1 ... 64
Verb      = "d" | "x" | "s" | "c" | "q" | "v" .
```

| Verb | Accepted argument types | Output |
| :--- | :--- | :--- |
| `%d` | every integer type, including named integer types and untyped integer/char constants | decimal |
| `%x` | integers | lowercase hex, no prefix (`-ff` for -255) |
| `%s` | underlying `string` or `[]u8` | the raw bytes |
| `%c` | underlying `u8` (untyped constants are converted to `u8`) | one raw byte |
| `%q` | `string` / `[]u8` | a double-quoted literal: `\n \r \t \\ \"`, `\xHH` (lowercase) for all other bytes `< 0x20`, `0x7f` and `>= 0x80` |
| `%v` | a named type with a Format method; `bool`; integers; `string` / `[]u8` | the method's output; `true`/`false`; decimal; raw bytes |
| `%%` | none | `%` |

- **Width** is the minimum number of bytes, at most 64. By default the
  text is right-justified with spaces. Flag `-` left-justifies. Flag `0`
  pads with zeros after the sign; it is only allowed with `%d` and `%x`
  and has no effect together with `-`.
- **The `%q` output** is always a valid FinCore and Go string literal, so it
  can be used directly when generating code.
- **Untyped constants** get their default type (`int`, `u8` for char
  literals, `bool`, `string`).

#### Format methods: the static "Stringer"

A named type `T` (also a generic instance) that declares

```go
func (t T) Format(dst []byte) usize
```

is printed by `%v` through this method. The method must be Total, have a
value receiver and have exactly this signature. Otherwise `%v` on `T` is an
error; it does not fall back to the underlying type. The checker resolves
the method at compile time, so there is no dynamic dispatch and there are
no interfaces.

The method receives the unwritten rest of the destination and must follow
the same contract: write from index 0, never more than `len(dst)` bytes,
and return the count. A larger result is clamped. A Format method may call
`formatTo` itself:

```go
type Point struct {
	x int
	y int
}

func (p Point) Format(dst []byte) usize {
	return formatTo(dst, "(%d, %d)", p.x, p.y)
}
```

With a width, the padding is computed from the count the method returns.
When the text is right-justified and less room is left than the width, the
method writes into a scratch buffer of `width` bytes. The padding is then
exact, and the result is still the truncated prefix.

#### Evaluation and effects

- `dst`, `format` and all arguments are evaluated left to right before
  anything is written. Each Format method is called once per directive.
- Totality: a `%v` directive that resolves to `T.Format` is a call edge from
  the caller to `T.Format` in the call graph. It takes part in SCC and
  mutual-recursion detection like a direct call. A Format method that
  formats its own type with `%v` is therefore rejected with E4002, and two
  Format methods that format each other are rejected with E4004.
- Scope: `dst` is only borrowed and `formatTo` retains nothing.
- Comptime: `formatTo` works inside `comptime func` bodies with the same
  semantics. Each formatted argument costs one unit of fuel.

### Grammar

No change. `formatTo` is an ordinary call. Its format language is the
directive syntax above, which applies to the constant string value.

### Universe (spec 2.4)

The builtin functions are now: `len`, `cap`, `copy`, `bytesEqual`,
`strBytes`, `bytesToStr`, `formatUint`, `parseUint`, `NewContext`,
`NewScope`, `panic`, **`formatTo`**. Like every predeclared identifier,
`formatTo` can be shadowed by a declaration of the same name.

### Error catalog (spec 11)

There are no new codes. The existing codes are used as follows:

| Code | formatTo diagnostics (position) |
| :--- | :--- |
| `E2002` TYPE_MISMATCH | `dst` not assignable to `[]byte` (dst argument); format not a constant string (format argument); malformed format, i.e. incomplete directive, unknown verb, flags or width on `%%`, width > 64, flag `0` on a verb other than `%d`/`%x` (format argument); argument not of class Value; argument type not accepted by its verb; invalid Format method (argument) |
| `E2003` ARITY_MISMATCH | number of arguments differs from the number of directives (format argument); fewer than two arguments (call) |
| `E2004` INVALID_NIL | untyped `nil` as an argument |
| `E4002` / `E4004` | recursion through Format methods without a measure |

### Runtime and code generation

Each call is lowered to an immediately called Go function literal over
`fincrt.Fmt` (`Lit`, `Int`, `Uint`, `Hex`, `HexInt`, `Str`, `Bytes`,
`Quote`, `QuoteBytes`, `Byte`, `Bool`, `Dst`/`Advance`). See
docs/runtime_api.md. finc0 and finc1 emit identical Go.

## Sum types

Enums with payloads plus `match` are FinCore's sum types. v0.2 makes them
usable for data models such as the self-hosted compiler's AST, types and IR:
matches are checked for exhaustiveness and reachability, `match` is also an
expression, arms take or-patterns and unqualified variant names, generic
enums work end to end, and the generated Go uses a compact layout.

### Grammar (diff against spec section 3)

```ebnf
Primary      = Literal
             | IDENT [ "[" TypeOrExpr { "," TypeOrExpr } "]" ]
             | "(" Expr ")"
             | FuncLit
             | StructLit
             | MatchExpr .                                   (* new *)

MatchStmt    = "match" Expr "{" { MatchArm ";" } "}" .
MatchArm     = Patterns "->" ( Expr | Block ) .              (* was: Pattern *)

MatchExpr    = "match" Expr "{" ExprArm { ( ";" | "," ) ExprArm } [ ";" | "," ] "}" .   (* new *)
ExprArm      = Patterns "->" Expr .                          (* new *)

Patterns     = Pattern { "|" Pattern } .                     (* new *)
Pattern      = "_" | IDENT [ "." IDENT ] [ "(" IdentList ")" ] | Literal .
```

Notes:

- A statement that starts with `match` is always a `MatchStmt`. A match
  expression appears wherever an operand may appear: `return`, the right
  side of `:=` / `=` / `var`, call arguments, conditions, operands of
  binary operators, struct field values, arms of other matches and constant
  initializers.
- The grammar stays LL(1). The scrutinee is parsed like an `if` condition
  (no struct literal at its top level without parentheses). The `{` must be
  on the same line as `match`.
- Arms are separated as statement arms are: a newline (automatic `;`) or an
  explicit `;`. Match expressions also accept `,`, which reads better on
  one line: `match c { Red -> 1, _ -> 2 }`. A trailing separator before
  `}` is allowed. A match expression needs at least one arm.
- `|` binds patterns only before `->`; in an arm body it is the bitwise OR
  operator. Literal patterns are single literals (no `-1`).
- Arms of a match expression are expressions, never blocks.

### Patterns

| Pattern | Meaning |
| :--- | :--- |
| `_` | matches anything (the "default" arm) |
| `Circle(r)`, `Rect(w, _)`, `Empty` | variant of the scrutinee's enum; binds the payload (`_` skips a position) |
| `Shape.Circle(r)` | the same, qualified with the enum type |
| `Option.Some(x)` | qualified with a generic enum's name, on any instance (`Option[u32]`) |
| `0`, `'a'`, `"s"`, `true`, `nil` | literal (scrutinee of a comparable non-enum type) |
| `K`, `pkg.K` | constant (not on enum scrutinees) |
| `P1 \| P2 \| ...` | or-pattern: matches if any alternative matches |

- **Unqualified variants.** If the scrutinee's type is an enum, an
  unqualified name that is one of its variants means that variant, even if
  a constant of the same name is in scope. Variant names are not symbols:
  they shadow nothing. Construction stays qualified (`Shape.Circle(2)`).
  Enums from imported packages are matched with unqualified patterns
  (`Some(x)`); `pkg.Type.Variant` is not a pattern.
- **Or-patterns** bind nothing: an alternative may not be `_` and may not
  bind a name other than `_`. Variants with payload are written with
  blanks, e.g. `Circle(_) | Empty`.
- Constants are not allowed as patterns on enum scrutinees (E2002); use the
  variant.

### Exhaustiveness and reachability (E2012)

Error code **E2012 `NON_EXHAUSTIVE_MATCH`** (both diagnostic tables):

- A `match` (statement or expression) on an **enum** without a `_` arm
  must cover every variant. Otherwise E2012 is reported at the `match`
  keyword, listing the missing variants in declaration order:
  `non-exhaustive match on Shape: missing Rect, Empty`.
- On **other types** (integers, bytes, bool, string) a match statement
  need not be exhaustive (no arm runs, as in Go). A match **expression**
  must have a `_` arm: `non-exhaustive match expression on u32: missing '_' arm`.
- **Unreachable arms** are E2012 too, at the pattern (or or-pattern
  alternative):
  - any arm after `_`: `unreachable match arm: it follows the '_' arm`;
  - a variant covered twice: `unreachable pattern: variant A is already covered`;
  - a literal or constant equal (by value) to an earlier one: `unreachable pattern: duplicate case 2`;
  - `_` after every variant is covered: `unreachable '_' arm: all variants of Shape are covered`.
- Coverage is checked only if every pattern of the match is valid, so a
  bad pattern produces one diagnostic, not a cascade.
- A match on an enum without `_` is exhaustive, so if all its arms
  terminate it is a terminating statement (decision 37): no `return`
  after it.

Spec section 11 gains one row:

| Code | Name | Description |
| :--- | :--- | :--- |
| `E2012` | `NON_EXHAUSTIVE_MATCH` | `match` on an enum misses variants, a match expression has no `_` arm, or an arm is unreachable |

### Match expressions

```go
area := match s {
	Circle(r) -> 3 * u64(r) * u64(r)
	Rect(w, h) -> u64(w) * u64(h)
	Empty -> 0
}
const Code = match Color.Green { Red -> 1; Green | Blue -> 2 }
if match t { Ident | Number -> true; _ -> false } { ... }
```

- **Types.** All typed arms must have identical types (E2002 `match arm has
  type u32, want u64`). Untyped constant arms take that type. If every arm
  is an untyped constant, the expression is untyped and its context fixes
  the type: `var b u8 = match c { Red -> 1; _ -> 255 }` checks each arm
  against `u8`; with no context the default type applies (`int`). Untyped
  int and untyped char arms mix to untyped int.
- Arms must have a value; `panic(...)` and calls without results are not
  arms of a match expression.
- **Constants.** A match expression is constant if its scrutinee is
  constant and the selected arm is a constant expression, so it can
  initialize a `const`. In `comptime` functions it is evaluated by the
  interpreter like any expression.
- **Layer 3.** Each arm is a separate branch. Payload bindings carry the
  scrutinee's origin and are borrowed (decisions 46 and 49): an arm may not
  consume a Linear binding. An arm that names a Linear variable moves it,
  so `k := match b { true -> a; _ -> c }` leaks `c` on the first path
  (E3005) unless it is closed. The origin of a match expression is the
  join of its arms.
- **Totality.** Arms are branches of the flow analysis. Patterns do not
  give facts: guard recursion with `if n == 0 { return ... }`, not with a
  `0 ->` arm.

### Compact layout (codegen)

An enum lowers to a Go struct with a tag and **shared payload slots**:

1. `_tag` is `uint8` for up to 256 variants, `uint16` up to 65,536,
   `uint32` beyond.
2. Payload Go types form **groups**, ordered by first appearance (variants
   in declaration order, payload positions left to right).
3. A group has as many slots as the largest number of payloads of that Go
   type in any **single** variant. Each variant maps its payloads of a type
   to that group's slots in order.
4. Slot `j` of a group is named `_<key>_<j>`. The key is the FinCore
   spelling of a basic type (`u8`, `u16`, `u32`, `u64`, `i8`..`i64`, `int`,
   `usize`, `bool`, `string`, `error`), otherwise the Go type when it is an
   identifier (named types such as `NodeID`, type parameters such as `T`,
   monomorphized names), otherwise the group's index in decimal. If an
   earlier group already uses the key, the index is used. An index cannot
   clash with an identifier key because it starts with a digit.
5. A constructor sets `_tag` (omitted for variant 0) and its own slots.
   Go zeroes the other slots, so the struct's `==` is variant equality
   (enums are comparable iff all payload types are).

```
type Shape enum { Circle(u32); Rect(u32, u32); Empty }
type Shape struct {
	_tag   uint8
	_u32_0 uint32
	_u32_1 uint32
}
Shape.Rect(3, 4)  =>  Shape{_tag: 1, _u32_0: uint32(3), _u32_1: uint32(4)}
```

Generic enums are Go generic structs whose layout is computed on the
declaration: type parameters are groups of their own (`Option[T]` has
`_T_0`, `Result[T]` has `_T_0` and `_error_0`). Enums with const
parameters are monomorphized and laid out per instance.

Memory, for an AST-like enum of 15 variants (payloads `u32`, `u64`, `u8`,
`bool` and up to three `NodeID`s) in an arena of 524,288 nodes:

| Layout | Fields | Size | Arena |
| :--- | :--- | :--- | :--- |
| v0.1 (one field per payload of every variant) | 30 | 128 B | 64.0 MiB |
| v0.2 (shared slots) | 9 | 48 B | 24.0 MiB |

### Lowering of `match`

- A match becomes `switch x._tag { case 0: ... }` (enums) or `switch x
  { case 1, 2: ... }` (other types). An or-pattern becomes one case list.
  The last arm of an exhaustive match is `default`, so Go also sees a
  terminating statement. Payload bindings that are used become `r :=
  x._u32_0`; if the scrutinee is not a local variable it is first stored in
  a temporary (`switch _fc_t0 := f(); _fc_t0._tag {`).
- A match expression becomes an immediately invoked function literal:
  `func() T { switch ... { case ...: return <arm> ... default: return <arm> } }()`.
- `return match ...` in a function with one result, outside `scope`
  blocks, is lowered without a literal: the switch is emitted in place and
  every arm returns its value (arms that are match expressions are
  lowered the same way, recursively).

### Example

```go
type Option[T any] enum {
	Some(T)
	None
}

func (o Option[T]) Or(d T) T {
	return match o {
		Some(x) -> x
		None -> d
	}
}

func classify(b byte) u32 {
	return match b {
		'0' | '2' | '4' | '6' | '8' -> 2
		'1' | '3' | '5' | '7' | '9' -> 1
		_ -> 0
	}
}
```

### Limitations

- Patterns are flat: no nested patterns (`Some(Circle(r))`) and no guards.
- Or-pattern alternatives cannot bind names.
- Imported enums can only be matched with unqualified patterns.
- Literal patterns cannot be negative.
- `true | false` does not make a bool match expression exhaustive; use `_`.
- Slot groups follow first appearance, not alignment, so Go may add
  padding (the example above would be 40 B with the `u64` slot first).
- Generic enums share slots only per type parameter, not per instance.
- Match expressions other than `return match` cost a function literal call
  (which Go may or may not inline).
