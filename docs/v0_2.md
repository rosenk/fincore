# FinCore v0.2

This document collects the changes to the v0.1 specification
(fincore_language_specification_v0_1.md). The binding decisions are
numbered in docs/semantics_decisions.md ("v0.2 additions": 58–61 std, 62–71 formatTo, 72–85 sum types, 86–93 ergonomics, 94–109 patterns; the std API is in docs/stdlib.md); the
runtime side is in docs/runtime_api.md.

## Language additions in v0.2

### `formatTo`: finitist, compile-time-checked formatting

```go
func formatTo(dst []byte, format string, args...) usize
```

`formatTo` writes the formatted text into `dst`, starting at index 0. It
truncates silently at `len(dst)` and returns the number of bytes written,
which is always `<= len(dst)`. The written bytes are always a prefix of the
untruncated output. The function is Total: it never allocates and never
panics. A buffer, a constant format and a byte count are all it needs, so
it fits the fixed-arena style of `compiler/`:

```go
var b [64]byte
n := formatTo(b[:], "mismatched types %v and %v", x.typ, y.typ)
return io.WriteStdout(b[:n])
```

The format must be a constant string. It is parsed and checked against the
arguments at compile time. Each call is then expanded into straight-line
calls on the runtime writer `fincrt.Fmt`, with no format parsing and no
reflection at run time.

#### Directives

```
Directive = "%" { "-" | "0" } [ Width ] Verb | "%%" .
Width     = decimal_digit { decimal_digit } .   // 1 ... 64
Verb      = "d" | "x" | "s" | "c" | "q" | "v" .
```

| Verb | Accepted argument types | Output |
| :--- | :--- | :--- |
| `%d` | every integer type, including named integer types and untyped integer/char constants | decimal |
| `%x` | integers | lowercase hex, no prefix (`-ff` for -255) |
| `%s` | underlying `string` or `[]u8` | the raw bytes |
| `%c` | underlying `u8` (untyped constants are converted to `u8`) | one raw byte |
| `%q` | `string` / `[]u8` | a double-quoted literal: `\n \r \t \\ \"`, `\xHH` (lowercase) for all other bytes `< 0x20`, `0x7f` and `>= 0x80` |
| `%v` | a named type with a Format method; `bool`; integers; `string` / `[]u8` | the method's output; `true`/`false`; decimal; raw bytes |
| `%%` | none | `%` |

- **Width** is the minimum number of bytes, at most 64. By default the
  text is right-justified with spaces. Flag `-` left-justifies. Flag `0`
  pads with zeros after the sign; it is only allowed with `%d` and `%x`
  and has no effect together with `-`.
- **The `%q` output** is always a valid FinCore and Go string literal, so it
  can be used directly when generating code.
- **Untyped constants** get their default type (`int`, `u8` for char
  literals, `bool`, `string`).

#### Format methods: the static "Stringer"

A named type `T` (also a generic instance) that declares

```go
func (t T) Format(dst []byte) usize
```

is printed by `%v` through this method. The method must be Total, have a
value receiver and have exactly this signature. Otherwise `%v` on `T` is an
error; it does not fall back to the underlying type. The checker resolves
the method at compile time, so there is no dynamic dispatch and there are
no interfaces.

The method receives the unwritten rest of the destination and must follow
the same contract: write from index 0, never more than `len(dst)` bytes,
and return the count. A larger result is clamped. A Format method may call
`formatTo` itself:

```go
type Point struct {
	x int
	y int
}

func (p Point) Format(dst []byte) usize {
	return formatTo(dst, "(%d, %d)", p.x, p.y)
}
```

With a width, the padding is computed from the count the method returns.
When the text is right-justified and less room is left than the width, the
method writes into a scratch buffer of `width` bytes. The padding is then
exact, and the result is still the truncated prefix.

#### Evaluation and effects

- `dst`, `format` and all arguments are evaluated left to right before
  anything is written. Each Format method is called once per directive.
- Totality: a `%v` directive that resolves to `T.Format` is a call edge from
  the caller to `T.Format` in the call graph. It takes part in SCC and
  mutual-recursion detection like a direct call. A Format method that
  formats its own type with `%v` is therefore rejected with E4002, and two
  Format methods that format each other are rejected with E4004.
- Scope: `dst` is only borrowed and `formatTo` retains nothing.
- Comptime: `formatTo` works inside `comptime func` bodies with the same
  semantics. Each formatted argument costs one unit of fuel.

### Grammar

No change. `formatTo` is an ordinary call. Its format language is the
directive syntax above, which applies to the constant string value.

### Universe (spec 2.4)

The builtin functions are now: `len`, `cap`, `copy`, `bytesEqual`,
`strBytes`, `bytesToStr`, `formatUint`, `parseUint`, `NewContext`,
`NewScope`, `panic`, **`formatTo`**. Like every predeclared identifier,
`formatTo` can be shadowed by a declaration of the same name.

## Sum types

Enums with payloads plus `match` are FinCore's sum types. v0.2 makes them
usable for data models such as the self-hosted compiler's AST, types and IR:
matches are checked for exhaustiveness and reachability, `match` is also an
expression, arms take or-patterns and unqualified variant names, generic
enums work end to end, and the generated Go uses a compact layout.

### Grammar (diff against spec section 3)

```ebnf
Primary      = Literal
             | IDENT [ "[" TypeOrExpr { "," TypeOrExpr } "]" ]
             | "(" Expr ")"
             | FuncLit
             | StructLit
             | MatchExpr .                                   (* new *)

MatchStmt    = "match" Expr "{" { MatchArm ";" } "}" .
MatchArm     = Patterns "->" ( Expr | Block ) .              (* was: Pattern *)

MatchExpr    = "match" Expr "{" ExprArm { ( ";" | "," ) ExprArm } [ ";" | "," ] "}" .   (* new *)
ExprArm      = Patterns "->" Expr .                          (* new *)

Patterns     = Pattern { "|" Pattern } .                     (* new *)
Pattern      = "_" | IDENT [ "." IDENT ] [ "(" IdentList ")" ] | Literal .
```

Notes:

- A statement that starts with `match` is always a `MatchStmt`. A match
  expression appears wherever an operand may appear: `return`, the right
  side of `:=` / `=` / `var`, call arguments, conditions, operands of
  binary operators, struct field values, arms of other matches and constant
  initializers.
- The grammar stays LL(1). The scrutinee is parsed like an `if` condition
  (no struct literal at its top level without parentheses). The `{` must be
  on the same line as `match`.
- Arms are separated as statement arms are: a newline (automatic `;`) or an
  explicit `;`. Match expressions also accept `,`, which reads better on
  one line: `match c { Red -> 1, _ -> 2 }`. A trailing separator before
  `}` is allowed. A match expression needs at least one arm.
- `|` binds patterns only before `->` (and after `is`); in an arm body it
  is the bitwise OR operator. The grammar of patterns, guards, tuple
  scrutinees and statement arm bodies was extended later in v0.2: see
  "Patterns" below.
- Arms of a match expression are expressions, never blocks.

### Patterns

| Pattern | Meaning |
| :--- | :--- |
| `_` | matches anything (the "default" arm) |
| `Circle(r)`, `Rect(w, _)`, `Empty` | variant of the scrutinee's enum; binds the payload (`_` skips a position) |
| `Shape.Circle(r)` | the same, qualified with the enum type |
| `Option.Some(x)` | qualified with a generic enum's name, on any instance (`Option[u32]`) |
| `0`, `'a'`, `"s"`, `true`, `nil` | literal (scrutinee of a comparable non-enum type) |
| `K`, `pkg.K` | constant (not on enum scrutinees) |
| `P1 \| P2 \| ...` | or-pattern: matches if any alternative matches |

- **Unqualified variants.** If the scrutinee's type is an enum, an
  unqualified name that is one of its variants means that variant, even if
  a constant of the same name is in scope. Variant names are not symbols:
  they shadow nothing. Construction stays qualified (`Shape.Circle(2)`).
  Enums from imported packages are matched with unqualified patterns
  (`Some(x)`); `pkg.Type.Variant` is not a pattern.
- **Or-patterns**: an alternative may not be `_`. Since the "Patterns"
  extension alternatives may bind variables if every alternative binds
  the same ones with identical types (`Circle(r) | Square(r)`).
- Constants are not allowed as patterns on enum scrutinees (E2002); use the
  variant.

### Exhaustiveness and reachability (E2012)

Error code **E2012 `NON_EXHAUSTIVE_MATCH`** (both diagnostic tables):

- A `match` (statement or expression) on an **enum** (or, since
  "Patterns", a tuple) must be exhaustive. Otherwise E2012 is reported at
  the `match` keyword, listing the missing variants in declaration order:
  `non-exhaustive match on Shape: missing Rect, Empty` (nested and tuple
  matches list witnesses, see "Patterns").
- On **other types** (integers, bytes, bool, string) a match statement
  need not be exhaustive (no arm runs, as in Go). A match **expression**
  must be exhaustive: `non-exhaustive match expression on u32: missing '_' arm`
  (a bool match is exhaustive with `true` and `false` arms).
- **Unreachable arms** are E2012 too, at the pattern (or or-pattern
  alternative):
  - any arm after `_`: `unreachable match arm: it follows the '_' arm`;
  - a variant covered twice: `unreachable pattern: variant A is already covered`;
  - a literal or constant equal (by value) to an earlier one: `unreachable pattern: duplicate case 2`;
  - `_` after every variant is covered: `unreachable '_' arm: all variants of Shape are covered`
    (`all values of T are covered` for other types, e.g. after `true` and `false`);
  - other alternatives covered by earlier arms (nested patterns): `unreachable pattern: it is covered by earlier patterns`.
- Coverage is checked only if every pattern of the match is valid, so a
  bad pattern produces one diagnostic, not a cascade.
- A match that is exhaustive (or on an enum or tuple, where E2012 enforces
  it) is a terminating statement if all its arms terminate (decision 37):
  no `return` after it.

Spec section 11 gains one row:

| Code | Name | Description |
| :--- | :--- | :--- |
| `E2012` | `NON_EXHAUSTIVE_MATCH` | `match` on an enum misses variants, a match expression has no `_` arm, or an arm is unreachable |

### Match expressions

```go
area := match s {
	Circle(r) -> 3 * u64(r) * u64(r)
	Rect(w, h) -> u64(w) * u64(h)
	Empty -> 0
}
const Code = match Color.Green { Red -> 1; Green | Blue -> 2 }
if match t { Ident | Number -> true; _ -> false } { ... }
```

- **Types.** All typed arms must have identical types (E2002 `match arm has
  type u32, want u64`). Untyped constant arms take that type. If every arm
  is an untyped constant, the expression is untyped and its context fixes
  the type: `var b u8 = match c { Red -> 1; _ -> 255 }` checks each arm
  against `u8`; with no context the default type applies (`int`). Untyped
  int and untyped char arms mix to untyped int.
- Arms must have a value; `panic(...)` and calls without results are not
  arms of a match expression.
- **Constants.** A match expression is constant if its scrutinee is
  constant and the selected arm is a constant expression, so it can
  initialize a `const`. In `comptime` functions it is evaluated by the
  interpreter like any expression.
- **Layer 3.** Each arm is a separate branch. Payload bindings carry the
  scrutinee's origin and are borrowed (decisions 46 and 49): an arm may not
  consume a Linear binding. An arm that names a Linear variable moves it,
  so `k := match b { true -> a; _ -> c }` leaks `c` on the first path
  (E3005) unless it is closed. The origin of a match expression is the
  join of its arms.
- **Totality.** Arms are branches of the flow analysis. Patterns do not
  give facts: guard recursion with `if n == 0 { return ... }`, not with a
  `0 ->` arm.

### Compact layout (codegen)

An enum lowers to a Go struct with a tag and **shared payload slots**:

1. `_tag` is `uint8` for up to 256 variants, `uint16` up to 65,536,
   `uint32` beyond.
2. Payload Go types form **groups**, ordered by first appearance (variants
   in declaration order, payload positions left to right).
3. A group has as many slots as the largest number of payloads of that Go
   type in any **single** variant. Each variant maps its payloads of a type
   to that group's slots in order.
4. Slot `j` of a group is named `_<key>_<j>`. The key is the FinCore
   spelling of a basic type (`u8`, `u16`, `u32`, `u64`, `i8`..`i64`, `int`,
   `usize`, `bool`, `string`, `error`), otherwise the Go type when it is an
   identifier (named types such as `NodeID`, type parameters such as `T`,
   monomorphized names), otherwise the group's index in decimal. If an
   earlier group already uses the key, the index is used. An index cannot
   clash with an identifier key because it starts with a digit.
5. A constructor sets `_tag` (omitted for variant 0) and its own slots.
   Go zeroes the other slots, so the struct's `==` is variant equality
   (enums are comparable iff all payload types are).

```
type Shape enum { Circle(u32); Rect(u32, u32); Empty }
type Shape struct {
	_tag   uint8
	_u32_0 uint32
	_u32_1 uint32
}
Shape.Rect(3, 4)  =>  Shape{_tag: 1, _u32_0: uint32(3), _u32_1: uint32(4)}
```

Generic enums are Go generic structs whose layout is computed on the
declaration: type parameters are groups of their own (`Option[T]` has
`_T_0`, `Result[T]` has `_T_0` and `_error_0`). Enums with const
parameters are monomorphized and laid out per instance.

Memory, for an AST-like enum of 15 variants (payloads `u32`, `u64`, `u8`,
`bool` and up to three `NodeID`s) in an arena of 524,288 nodes:

| Layout | Fields | Size | Arena |
| :--- | :--- | :--- | :--- |
| v0.1 (one field per payload of every variant) | 30 | 128 B | 64.0 MiB |
| v0.2 (shared slots) | 9 | 48 B | 24.0 MiB |

### Lowering of `match`

- A match becomes `switch x._tag { case 0: ... }` (enums) or `switch x
  { case 1, 2: ... }` (other types). An or-pattern becomes one case list.
  The last arm of an exhaustive match is `default`, so Go also sees a
  terminating statement. Payload bindings that are used become `r :=
  x._u32_0`; if the scrutinee is not a local variable it is first stored in
  a temporary (`switch _fc_t0 := f(); _fc_t0._tag {`).
- A match expression becomes an immediately invoked function literal:
  `func() T { switch ... { case ...: return <arm> ... default: return <arm> } }()`.
- `return match ...` in a function with one result, outside `scope`
  blocks, is lowered without a literal: the switch is emitted in place and
  every arm returns its value (arms that are match expressions are
  lowered the same way, recursively).

### Example

```go
type Option[T any] enum {
	Some(T)
	None
}

func (o Option[T]) Or(d T) T {
	return match o {
		Some(x) -> x
		None -> d
	}
}

func classify(b byte) u32 {
	return match b {
		'0' | '2' | '4' | '6' | '8' -> 2
		'1' | '3' | '5' | '7' | '9' -> 1
		_ -> 0
	}
}
```

Tests: `testdata/pass/pass_sum_types.fc`, `testdata/pass/pass_sum_types_pkg/`,
`testdata/fail/fail_match_*.fc`, `testdata/fail/fail_enum_recursive.fc`,
`scripts/diffcheck/cases/sum_*.fc`, `scripts/diffbuild/cases/cg_sum_types.fc`
and the Go unit tests in `bootstrap/internal/{parser,types,scope,totality,codegen/golang}`.

### Limitations

- Nested patterns, binding or-patterns, guards, tuple scrutinees, rest
  patterns, `is`, negative literal patterns and statement arm bodies were
  added later in v0.2 (see "Patterns"); a bool match is now exhaustive
  with `true` and `false` arms.
- Imported enums can only be matched with unqualified patterns.
- Slot groups follow first appearance, not alignment, so Go may add
  padding (the example above would be 40 B with the `u64` slot first).
- Generic enums share slots only per type parameter, not per instance.
- Match expressions other than `return match` cost a function literal call
  (which Go may or may not inline).

## Ergonomics

Three small conveniences, binding decisions 86–93 in
docs/semantics_decisions.md. They replace decision 10 (no automatic `&`)
and the "no string `+`" part of decision 26. None of them adds run-time
work that was not already expressible: each one is a rewrite into a v0.1
form.

### Auto-& for pointer-receiver method calls

```go
var v vec.Vec[8, u32]
v.Push(7)              // was: vp := &v; vp.Push(7)
cells[i].Inc()         // array or slice element
p.list.Truncate(0)     // field through a pointer
n, _ := diags.text.At(0)
```

`x.M(...)`, where `M` has a pointer receiver and `x` has type `T`, means
`(&x).M(...)` when `x` is addressable — exactly the operands an explicit
`&` accepts: variables (locals, parameters, receivers, globals, payload
bindings), `x.f` of an addressable struct or through a pointer, `a[i]` of
an addressable array (or a pointer to one), `s[i]` of a slice, and `*p`.
Anything else is E2002:

```
cannot call pointer method Inc on fresh() (type Counter): value is not addressable
```

(call results, struct literals, conversions, constants, match
expressions, and fields or elements of such values). Method values stay
unsupported (`f := v.Push` is E2002, decision 32), and value-receiver
methods are still callable through pointers.

The implicit `&` is checked exactly like an explicit one: the scope
checker gives the call the origin of `&x` and marks `x` address-taken
(S1–S5, decisions 43–45), so `c.Self()` on a local `c` may be used
locally but not returned or stored where it outlives `c`
(`testdata/fail/fail_auto_addr_escape.fc`); the totality checker treats
`x` as address-taken (a loop bound `a.len` is not invariant across
`a.Pop()`; copy it first); comptime evaluation passes a pointer to the
variable's cell. Go output keeps the call as written, `x.M()`, since Go's
addressability rules are the same.

### Constant strings as `[]byte`

```go
if bytes.HasPrefix(line, "go ") { ... }   // was: strBytes("go ")
io.WriteStdout("done\n")
return Msg{text: "hello"}
k := copy(dst[:], Prefix)
```

An untyped string constant — a literal, an untyped constant or a
constant expression — may be used wherever a value of a type with
underlying type `[]u8` is required: assignments and typed `var`
declarations, arguments (user functions and methods, builtins such as
`bytesEqual` and `formatTo`'s `dst`, capability methods, generic
functions with explicit type arguments such as `id[[]byte]("x")`),
`return`, struct literal fields, and the source of `copy` into a `[]u8`.
The value is a fresh copy every time, exactly `strBytes("...")`: writing
to it never changes a shared static. It has no scope origin, so it may be
returned or stored like the result of `strBytes`. Go output is
`[]byte("...")` (or `[]byte(Name)` for a named constant).

Not converted:

- typed strings, constants included (`const S string = "x"`, `s := "x"`):
  use `strBytes(s)`; E2002 `cannot use s (type string) as type []u8 in ...`;
- comparisons: `[]byte` is not comparable, so `b == "x"` stays E2002; use
  `bytesEqual(b, "x")`;
- `x := "abc"` and untyped `var`: the default type is still `string`, and
  a type parameter `T` (also `any`-constrained) is never inferred as
  `[]byte` (generic calls need explicit type arguments anyway);
- package-level `var` initializers (the result is not a constant) and
  arguments of comptime calls (which must be constants).

### Constant string concatenation

```go
const MainSig = "want driver func main(<capabilities>) error"

n := formatTo(buf[:], "invalid main signature: %s (" + MainSig + ")", x)
```

`+` on two constant strings is a constant string, folded at compile time:
usable in `const` declarations, as a formatTo format (which must be
constant, decision 63), with `len`, and as an implicit `[]byte`. A
non-constant operand is E2002 at the operator — FinCore still never
builds strings at run time:

```
invalid operation: name is not a constant (string concatenation is only allowed for constants)
```

Inside a comptime function, parameters and locals are not constants, so
the same rule applies there: only true constants are folded. Go output
contains the folded literal.

## Patterns

v0.2 extends `match` so that sum-type code needs neither duplicated arms
nor nested matches nor one-line predicates: or-patterns bind variables,
patterns nest, a match may take a tuple of values, `..` skips payloads,
arms take guards, `x is Pattern` tests a variant, and a statement arm may
be a single simple statement. Decisions 94–109 in
docs/semantics_decisions.md; both compilers implement everything
identically (diagnostics and generated Go byte for byte).

```go
func size(t Ty) u32 {
	return match t {
		Struct(r, n) | Array(r, n) -> r * n   // binding or-pattern
		Slice(r, ..) -> r                      // rest pattern
		Sig(.., last) -> last
		Named(_) | Ptr -> 8
	}
}

func equalVals(a Val, b Val) bool {
	return match (a, b) {                    // tuple scrutinee
		(Int(h1, l1), Int(h2, l2)) -> h1 == h2 && l1 == l2
		(Code(Pair(x, _)), Code(Pair(y, _))) if x == y -> true   // nested, guard
		_ -> false
	}
}

if v is Int(h, l) && h == 0 {             // variant test with bindings
	return l
}
match ts[i] {
	Named(_) -> n--                       // simple-statement arm bodies
	Ptr -> continue
	Struct(r, _) -> last = r
	Sig(..) -> return 0
}
```

### Grammar (diff against "Sum types" above)

Lexer: `is` is a new keyword; `..` is a new token (`...` is unchanged).

```ebnf
Expr         = UnaryExpr | Expr binary_op Expr | Expr "is" Patterns .   (* new: "is" *)
MatchStmt    = "match" Scrutinee "{" { MatchArm ";" } "}" .
MatchExpr    = "match" Scrutinee "{" ExprArm { ( ";" | "," ) ExprArm } [ ";" | "," ] "}" .
Scrutinee    = Expr | "(" Expr "," Expr { "," Expr } ")" .             (* new: tuple *)
MatchArm     = Patterns [ Guard ] "->" ArmBody .
ArmBody      = Block | Expr | SimpleStmt | "return" [ ExprList ] | "break" | "continue" .  (* new *)
ExprArm      = Patterns [ Guard ] "->" Expr .
Guard        = "if" Expr .                                                (* new *)

Patterns     = Pattern { "|" Pattern } .
Pattern      = "_" | VariantPat | LitPat | "(" Patterns { "," Patterns } ")" .
VariantPat   = IDENT [ "." IDENT ] [ "(" [ PayloadPat { "," PayloadPat } ] ")" ] .
PayloadPat   = ".." | PayloadAlt { "|" PayloadAlt } .                     (* new *)
PayloadAlt   = IDENT | VariantPat | LitPat | "(" PayloadPat { "," PayloadPat } ")" .
LitPat       = Literal | "-" INT .                                        (* new: "-" INT *)
```

- `is` has the precedence of the relational operators (`<`, `<=`, `>`,
  `>=`): `a + b is X` is `(a + b) is X`, and `x is A && y is B` needs no
  parentheses. The pattern after `is` extends over `|`: `x is A | B`.
- A scrutinee that starts with `(` and has a top-level `,` before the
  matching `)` is a tuple. Tuples exist nowhere else: `(a, b)` in any other
  position is a syntax error, and a tuple that ends up inside a larger
  expression (`match (a, b) + 1 {`) is E2002 `tuple (a, b) can only be the
  scrutinee of a match`.
- In a payload position a bare identifier (not followed by `.` or `(`) is
  a `PayloadAlt` IDENT: a binding, `_`, or a variant of the payload's enum
  type (decided by the type checker). Everywhere else (top level, tuple
  elements) a bare identifier is a variant or a constant, as before.
- `(P)` is a parenthesized pattern; with a comma it is a tuple pattern
  (only valid against a tuple scrutinee).
- A statement arm whose body is a simple statement, `return`, `break` or
  `continue` is parsed as a one-statement block (the AST has no new arm
  form). `:=` is rejected there (E1001 `cannot declare variables in a
  match arm without a block`). Match expressions keep expression arms.
- AST (both dumps): `MatchArm.Guard` (between `Pattern` and `Expr`),
  `CtorPattern.Args` (was `Bindings`; elements are `Ident`,
  `CtorPattern`, `LiteralPattern`, `OrPattern` or `RestPattern`), new
  nodes `TuplePattern{Elems}`, `RestPattern`, `TupleExpr{Elems}`,
  `IsExpr{X, Pattern}`.

### Pattern semantics

| Pattern | Matches |
| :--- | :--- |
| `_` | anything |
| `x` (payload position) | anything; binds `x` to the payload (borrowed, origin of the scrutinee) |
| `V`, `V(p1, ..., pn)`, `T.V(...)` | variant `V`, each payload matching its pattern |
| `V(p, ..)`, `V(.., p)`, `V(..)` | `..` stands for the remaining payloads (at most one per list, any position; `V(..)` is valid even for a payload-less `V`) |
| `0`, `-1`, `'a'`, `"s"`, `true`, `nil`, `K` | a value equal to the literal / constant (`K` only at the top level or in tuple elements) |
| `P1 \| P2` | either alternative; alternatives bind the same variables |
| `(P1, ..., Pn)` | a tuple scrutinee of arity n, element-wise |

- **Payload identifiers.** If the payload's type is an enum and the name is
  one of its variants without payload, the identifier is that variant
  (`Some(None)`); the name is still declared and bound to the payload
  (which is that variant). Any other name binds the payload, shadowing
  constants of the same name; use a literal to compare with a value.
- **Or-pattern bindings.** Every alternative must bind the same set of
  names, each with an identical type; otherwise E2002 (`or-pattern
  alternatives must bind the same variables (x is not bound here)`, `...
  (x is not bound in the first alternative)`, `variable x has type bool
  here but u32 in the first alternative`). A name bound twice within one
  alternative is E2002 `variable x is bound more than once in a pattern`.
  An alternative may not be `_` (E2002, also in payload or-patterns).
  Linear payloads are borrowed in every alternative, so linearity is
  consistent automatically (the types are identical).
- **Guards.** `P if cond -> body`: `cond` is a bool expression (E2002
  `non-boolean guard c in match arm (type u32)`) evaluated after the
  pattern matched and its bindings were assigned; if it is false, matching
  continues with the next arm. A guarded arm counts neither for
  exhaustiveness nor for making later arms unreachable.
- **`is`.** `e is P` is a bool expression; `e` is evaluated once. It may
  bind variables only when it is the condition of an `if` or a conjunct of
  the condition's top-level `&&` chain; the bindings are visible in the
  later conjuncts and in the then block, not in the else branch. Elsewhere
  a binding is E2002 `cannot bind x: an 'is' pattern can bind variables
  only in the condition of an if statement` (if the name is also used, the
  resolver reports E2001 `undefined: x` first). `e is P` without bindings
  on a constant `e` is a constant.
- **Tuple scrutinee.** `match (e1, ..., en)` evaluates the elements left to
  right, once. The arms' patterns are tuple patterns of arity n or `_`
  (E2003 `tuple pattern has 3 elements, scrutinee has 2`; E2002 for a
  non-tuple pattern). The scrutinee's type prints as `(T1, ..., Tn)`.

### Usefulness, reachability and exhaustiveness

Both checkers implement Maranget's usefulness algorithm ("Warnings for
pattern matching", JFP 2007; finc0 `types/usefulness.go`, finc1
`check_match.fc`). A pattern matrix has one column per scrutinee value (n
for a tuple, else 1) and one row per top-level or-alternative of the
unguarded arms; bindings and `..` are wildcards. A row `q` is *useful*
with respect to a matrix `P` if some value matches `q` and no row of `P`:

```
U(P, ())        = P has no rows
U(P, (c(r..), q..)) = U(S(c, P), (r.., q..))           -- c a constructor or literal
U(P, (p1|p2, q..))  = U(P, (p1, q..)) or U(P, (p2, q..))
U(P, (_, q..))  = OR over all constructors c of U(S(c, P), (_.., q..))   if the column is complete
                = U(D(P), (q..))                                          otherwise
```

`S(c, P)` keeps the rows whose first pattern is `c` (replaced by its
arguments) or a wildcard (replaced by wildcards); `D(P)` keeps the rows
with a wildcard first, without it; or-patterns are expanded when they
reach the first column. Constructors: the variants of an enum (in
declaration order, arity = payload count), `true` and `false` for bool;
every other type is an infinite domain of literals, so its column is
never complete. Recursion is bounded by a fuel of 1000 (when it runs out
an alternative counts as reachable and the match as exhaustive).

- **Unreachable** (E2012, at the alternative): an alternative is
  unreachable if it is not useful with respect to the rows of the earlier
  unguarded arms and the earlier alternatives of its own arm. Messages,
  checked in this order: any arm after an unguarded top-level `_` arm
  `unreachable match arm: it follows the '_' arm` (once per arm);
  `_` `unreachable '_' arm: all variants of T are covered` (enums) /
  `all values of T are covered` (others); a variant whose payload patterns
  are all bindings, `_` or `..` `unreachable pattern: variant V is already
  covered`; a literal or constant `unreachable pattern: duplicate case X`;
  anything else `unreachable pattern: it is covered by earlier patterns`.
  Redundant alternatives *inside* a nested or-pattern (`Some(1 | 1)`) are
  not reported.
- **Exhaustiveness** (E2012, at `match`): the wildcard row must not be
  useful with respect to all unguarded rows. Enum and tuple matches must
  be exhaustive; match expressions on other types too (`missing '_' arm`,
  unchanged); match statements on other types need not be.
- **Counts as exhaustive** (terminating statements, decision 37; scope,
  linearity and totality flow): the unguarded arms are exhaustive, or the
  scrutinee is an enum or a tuple (E2012 reports the rest; no cascading
  E2003). If a pattern is invalid, coverage is not checked and the match
  counts as exhaustive if its scrutinee is an enum or tuple or it has an
  unguarded `_` arm.

### Witness format

`non-exhaustive match on T: missing W1, W2, ...` lists missing patterns
(witnesses) computed by the same recursion, constructor by constructor in
declaration order:

- a constructor present in the column is specialized and prefixes the
  witnesses of the specialized matrix;
- a missing constructor, with `_` for each payload, is combined with the
  witnesses of the default matrix;
- a column of an infinite domain, or one without any constructor (except
  at the top of a non-tuple scrutinee, where the missing variants are
  always listed), contributes `_`.

Witnesses are printed as patterns: `Some(Rect(_, _))`, `false`, `_`; for a
tuple scrutinee as `(W1, ..., Wn)`. At the top of a non-tuple scrutinee a
missing variant whose payloads are all `_` is printed by name alone, so
flat matches keep their v0.2 messages (`missing Rect, Empty`). At most 32
witnesses are listed; more are elided with `, ...`. Examples:

```
non-exhaustive match on Shape: missing Rect, Empty
non-exhaustive match on Option[Shape]: missing Some(Rect(_, _))
non-exhaustive match on Opt[u32]: missing Some(_)
non-exhaustive match on (Val, Val): missing (Int(_, _), Bool(_)), (Int(_, _), Str(_)), (Str(_), _)
non-exhaustive match on (bool, bool, bool): missing (true, false, _), (false, _, true)
```

### Lowering

- A match whose arms are all flat (no tuple scrutinee, no guard, every
  alternative `_`, a literal, a constant or a variant whose payload
  patterns are bindings, `_` or `..`, with bindings only outside
  or-patterns) is lowered to a Go `switch` exactly as before (a `..`
  only shifts the slots of the bindings after it). The last arm of a
  match that counts as exhaustive becomes `default`.
- Every other match is an `if` / `else if` chain over the scrutinee:
  - The scrutinee is stored in temporaries `_fc_tN := e` (one per tuple
    element, in order) unless every element is a local variable and no
    arm has a guard; an unused temporary gets `_ = _fc_tN`.
  - Each arm's condition tests `_tag` and payload slots along the
    pattern's paths, e.g. `o._tag == 0 && o._T_0._tag == 0 &&
    o._T_0._T_0 == uint32(0)`; or-patterns become parenthesized `||`
    groups; bindings and `_` add no test.
  - A guard is `cond && (guard)`, or, if it reads bindings,
    `cond && func() bool { x := path; return guard }()`: the bindings are
    assigned before the guard is evaluated.
  - The arm body starts with the bindings it reads (`x := path`); a
    binding or-pattern declares `var x T` and assigns it in an if chain
    over the alternatives' tests.
  - The last arm of an exhaustive match is the final `else`, so Go sees a
    terminating statement. Match expressions and `return match` use the
    same chain with `return` in every arm.
- `e is P` is `(path tests)` if `e` is a local variable or the test reads
  the value once (a flat variant or literal pattern), otherwise
  `func() bool { _fc_tN := e; return tests }()`. With bindings (if
  conditions only) the if statement is wrapped in a block declaring
  `var x T` for the bindings that are read, and the function literal
  assigns them when the test succeeds:
  `{ var l uint32; if func() bool { _fc_t0 := v; if _fc_t0._tag == 0 { l = _fc_t0._u32_1; return true }; return false }() && ... { ... } }`.
- Comptime evaluates all forms: tuple scrutinees, nested and or-patterns
  with bindings, guards (after binding) and `is`.

### Limitations

- Bindings are allowed only in payload positions; a tuple element or the
  top level of an arm cannot bind the whole value (use the scrutinee
  expression).
- Constants are patterns only at the top level and in tuple elements; in
  payload positions a name binds.
- Literal domains are treated as infinite: `Some(0) | Some(1) | ...` never
  covers a `u8` payload, and a `u8` match expression needs `_`.
- Redundant alternatives inside nested or-patterns are not reported.
- `is` binds only in if conditions (not in `for` conditions or elsewhere).
- Patterns give the totality checker no facts (decision 79): guard
  recursion with `if`, not with `0 ->` arms or `is`.
- Guards that read bindings and `is` tests on non-variables cost a
  function literal call.
- Up to 32 witnesses are listed; the usefulness recursion has a fuel of
  1000.
