# FinCore v0.1 — resolved spec ambiguities (binding for finc0 and compiler/)

The test corpus in testdata/ is written against these decisions. Conventions for tests: testdata/README.md.

1. **Linear parameters.** A Linear param of a `driver func` is OWNED by the callee (must be consumed on all paths; the caller's argument is moved). A Linear param of a total `func` is BORROWED (caller keeps ownership; callee must not consume it).
2. **E3005 location:** at the binding site of the leaked resource (`:=` line, or the func header line for a parameter).
3. **Error-path refinement:** for `(Linear, error)` results (ListenTCP, Accept, AcquireSlot, NotifyContext, NewContext...), the Linear value is not live on the `err != nil` path.
4. **comptime funcs** are not totality-checked; bounded by fuel. E4001 points at the evaluation root (e.g. the `const X = F(0)` line).
5. **E4004** reported once per SCC, at the first function in source order.
6. **E3001 beats E2005** for package-level `var g Conn`.
7. Assignment from a `conns.Go` closure to a captured outer variable is a write to that variable → S2 applies (E3002).
8. Plain `for` loops are totality-checked even inside `driver` funcs; only `driver for` is exempt.
9. Totality forms that must be accepted: `for i := usize(0); i < b; i++` / `i += k` / `i > 0; i -= k`; `for lo < hi decreases(hi - lo)` with `lo = mid + 1` / `hi = mid`; slice shrink with `if n == 0 { return ... }` before `rem = rem[n:]`.
10. ~~No automatic `&` for pointer-receiver method calls (`ap := &arena; ap.Push(..)`).~~ **Superseded by 86** (v0.2: `x.M()` on an addressable `x` means `(&x).M()`).
11. Generics require explicit type args (`id[u64](42)`). Types with const params (`Vec[N usize, T any]`) are monomorphized in Go output.
12. Enums: `Shape.Circle(2)`, `Shape.Empty`; patterns `Shape.Rect(w, h)`, int literals, `_`. Expr arms are expressions only.
13. No array literals (grammar has none).
14. Go-like: untyped int consts, `:=` may redeclare `err` if ≥1 new var, `if init; cond`, errors compared with `==`, defer args evaluated at defer, `bytesToStr` copies.
15. Local imports resolve relative to the module root (cwd of finc); exported names are capitalised.
16. `main` params must be a subset of {Net, Signals, Clock, FS, Env, Stdio, Exec}; unused caps allowed.
17. `--race` requires cgo: finc0 sets CGO_ENABLED=1 for race builds only.
18. Runtime deviations: see docs/runtime_api.md (`ErrParse` sentinel is part of the universe).

## Parser decisions (M0)
19. Keywords: exactly the 24 listed in §2.3 (the "27" count is a typo). `Code`/`El` are predeclared identifiers, contextual keywords in type position.
20. Go-style: no `T{` composite literal at top level of `if/for/match/scope` headers; multi-line arg lists need trailing commas; semicolons may be omitted before `)`/`}`.
21. Match arm body must be an Expr or Block (`x -> pos++` is invalid; use `x -> { pos++ }`).
22. Variadic `xs ...T` allowed for the last parameter only.
23. No decimal literals with leading zero; ASCII identifiers only; compound assign needs exactly one value per side; `for` post clause cannot be `:=`.
24. AST nodes have dense post-order NodeIDs (shared IDAlloc across files); later passes annotate via side tables indexed by NodeID (see bootstrap/internal/ast/doc.go).

## Type checker decisions (M1)
25. Untyped int defaults to `int`; `len`/`cap` return `usize`; char literals are untyped, default `u8`.
26. Typed constant overflow is E2002; comptime arithmetic wraps to the static type. ~~No string `+`.~~ String `+` **superseded by 91** (v0.2: constant operands only).
27. Package-level `var` initializers must be constant expressions (struct literals of consts and payload-less variants count).
28. Comptime calls outside comptime bodies are folded and need constant args; const initializers may call only comptime funcs.
29. Fuel: fresh budget per evaluation root; call/iteration/index cost 1; recursion cap 10_000 frames (E4001); E4003 index OOB; E5001 for driver/panic in comptime.
30. Code constructors are level-polymorphic; CodeUniv(n) needs const n; bare `Code` is E2010. Extension: `CodeField(name, c) FieldCode`. CodeEmpty → `enum{}`, CodeUnit → `struct{}`.
31. Type params range over Value types only; operators/conversions on type-param values are E2011; no method type params.
32. Value-receiver methods callable on `*T`; pointer-receiver methods need `*T` or (v0.2, decision 86) an addressable `T`; no method values (also not for pointer-receiver methods on addressable operands); no `&T{}`.
33. nil: pointer/Scoped → E2004; other non-error/non-slice → E2002; `x := nil` → E2004.
34. Missing Scoped field in struct literal / uninitialized Scoped local (incl. pointers) → E2005.
35. Total func value assignable to `driver func` type, not vice versa.
36. All capability methods are Total except `Exec.Run` (Driver); `panic` is Driver.
37. Missing return is E2003 (Go terminating-statement rules; exhaustive `match` terminates).
38. Expression statements / defer / expr match arms must be calls.
39. Redeclaration E2001; `:=` without new var and stray break/continue E2002; `decreases` measure assignable to usize.
40. `main` checked (E5002) only when the root package is `main`; capabilities distinct; no variadics.
41. Imports: clean relative paths; local name = package clause name unless aliased.
42. `Clock` has no methods; fincrt needs a `Clock` type for main injection.

## Scope checker decisions (M2a)
43. Slices are tracked by where their memory lives: slices of global arrays are depth 0; `buf[:]` of a local carries the local's depth (`return buf[:]` → E3002).
44. Each parameter is its own region at caller level: returning a parameter (or derived value) is allowed; storing one param into memory reached via another (`p.f = q`) or `&local` through a receiver is E3002.
45. Resource-constructor calls tie the result only to their arguments (this is how the S3 exemption extends to user code).
46. Consuming a borrowed Linear (total-func param, receiver, match binding, non-Go literal capture) is E3003.
47. After `defer x.Close()` / `defer cancel()`, explicit closes and later uses remain allowed; double close without defer is E3003.
48. Immediately-called literals are summarised (consume / borrow / E3005 if closed on some paths only); stored literals only borrow Linear captures.
49. A Linear struct is tracked as one unit. E3004 covers `_ = x`, `_` in `:=`/`=`, Linear-valued expression statements and match-arm expressions.
50. Error-path refinement recognises only bare `err != nil` / `err == nil`. `panic` ends a path without leak checks.
51. Pass order: scope, then totality; the pipeline stops at the first pass reporting errors.

## Totality checker decisions (M2b) — see bootstrap/internal/totality/doc.go for exact accepted shapes
52. Missing measure: E4002 at the func (self-recursion) / E4004 once per SCC (mutual). Non-decreasing in-SCC call: E4002/E4004 at the call. Bad measure (not an unassigned unsigned param) at the `decreases` clause.
53. Loops with `decreases` → T3 only; `len(s) > 0` loops → T2 only; others → T1.
54. T1: `<=`/`>=` only with overflow-safe constant bound; step > 1 needs constant/len/cap bound; `i > 0; i -= 2` on unsigned rejected. Bounds reached through pointers/globals are invalidated by any memory-writing call — copy to a local first (`lim := p.ntok`).
55. T3 loops accept `x++`/`x--`/midpoint `a + (b-a)/k` updates; `(lo+hi)/2` rejected (overflow).
56. Calls through function values add edges to every escaping total func; inside a cycle they are rejected.
57. compiler/: 33 Parser methods carry decreases; the Parser SCC has 31 members.

## v0.2 additions — see docs/v0_2.md and docs/stdlib.md

### Standard library — details in docs/stdlib.md
58. **Standard library imports.** An import path that is `std` or starts with `std/` resolves to `$FINCROOT/<path>` when the environment variable `FINCROOT` is set and non-empty (a relative value is relative to the working directory), otherwise to `<moduleRoot>/<path>` like every local import (15, 41). The directory is joined and cleaned lexically; files of FINCROOT packages are named `$FINCROOT/<path>/<file>.fc` in diagnostics (never made relative to the working directory, so finc0 and finc1 print the same names). A missing package gives the usual E2001 messages naming that directory. `FINCORE_ROOT` (the fincore Go module used by `build`) is unrelated. API reference: docs/stdlib.md.
59. **std conventions.** std packages are ordinary packages: every function Total (T1-T3), no capabilities, no `driver`, no panic. Capacities are const type parameters. Overflow is reported by a `false`/`ok` result and, for arena-like types, a sticky flag (`Full`, `Truncated`), never by growing or panicking. IDs and run starts handed out by std containers start at 1 (0 = none / empty run). Hash tables store entries densely in insertion order and buckets hold entry numbers only, so iteration order is independent of hashing. `bytes.Builder` writes are all-or-nothing. Keys are concrete types (`U64Map`, `StrMap`, `Interner`, caller-keyed `Table`) because operators on type parameters are E2011 (31).
60. **Const type parameters are invariant T1 bounds.** In `for i := usize(0); i < N; i++` (also `i < N*2`, `for i := N; i > 0; i--`) a const type parameter `N` counts as a constant of every instance, like a named constant. The other T1 rules are unchanged: `<=`/`>=` and steps > 1 still need a constant (not a parameter) or a len/cap bound.
61. **Function types need parameter names** (grammar: `ParamDecl = IDENT {"," IDENT} Type`): write `less func(a T, b T) bool`, not `func(T, T) bool`. Function values (named functions, literals, variables) may be passed to generic functions; by 56 the call through the value adds edges to every escaping total function, so a comparison function that (transitively) calls the sort it is passed to closes an unmeasured cycle (E4004).
### `formatTo` — details in docs/v0_2.md
62. **`formatTo(dst []byte, format string, args...) usize`** is a predeclared builtin (universe, inserted after `panic`; shadowable like `len`). It writes the formatted text into `dst` from index 0, silently truncates at `len(dst)` and returns the number of bytes written (always `<= len(dst)`); the written bytes are always a prefix of the untruncated output. It is Total: no allocation, no panic. Like `copy` it may be used as an expression statement.
63. **Format string.** `format` must be a constant expression assignable to `string`, else E2002 at the format argument (`format argument f to formatTo must be a constant string`). A directive is `%` [flags] [width] verb: flags are any sequence of `-` (left-justify) and `0` (zero pad; ignored together with `-`), width is a decimal number `<= 64`, verbs are `d x s c q v`; `%%` is a literal `%` and takes no flags or width. Malformed directives — incomplete at the end of the format, unknown verb, `%5%`, width > 64, flag `0` with a verb other than `d`/`x` — are E2002 at the format argument (`invalid format for formatTo: ...`, first one only; the arguments are still checked and default-typed). Width pads with spaces on the left (right-justify) or, with `-`, on the right; with `0`, numbers are padded with `0` after the sign. Widths count bytes. A flag without width has no effect.
64. **Arguments.** The number of arguments after `format` must equal the number of directives: E2003 (ARITY_MISMATCH, consistent with every other builtin) at the format argument; fewer than 2 arguments in total is E2003 at the call. Each argument must be of class Value (E2002 `cannot format x (type T): formatTo arguments must be Value types`) and accepted by its verb (E2002 `cannot use x (type T) as argument for %d in formatTo`); both are reported at the argument, and every argument is checked. Untyped constants get their default type (decision 25), for `%c` they are converted to `u8`; failures of that conversion are the usual E2002 (overflow, wrong kind) / E2004 (nil).
65. **Verbs.** `%d`: any integer (underlying integer type, incl. named types like `Duration`, `Celsius i32`), decimal. `%x`: integers, lowercase hex without prefix; negative values print `-` and the hex magnitude. `%s`: underlying `string` or `[]u8` (not `[]T` for a named `T` such as `[]Signal`), raw bytes. `%c`: underlying `u8`, one raw byte. `%q`: `string`/`[]u8`, double-quoted with `\n \r \t \\ \"` and `\xHH` (lowercase) for every other byte `< 0x20`, `0x7f` and every byte `>= 0x80`; the result is always a valid FinCore and Go string literal. `%v`: a user named type (or generic instance) that has a method named `Format` is printed by that method; otherwise `bool` (`true`/`false`), integers (decimal), `string`/`[]u8` (raw). The method must be a Total, value-receiver, non-variadic `Format(dst []byte) usize` (exactly these types), else E2002 at the argument — there is no fallback to the underlying type. Resolution is static (no dynamic dispatch); a struct field named `Format` is not a method.
66. **Format methods.** A Format method receives the unwritten rest of `dst` (`len == cap ==` remaining room) and must obey the same contract (write from index 0, return the count; a larger result is clamped). With a width it is padded according to the returned count. When right-justifying into less room than the width, the method writes into a width-byte scratch buffer instead, so the padding (and therefore the truncated prefix) is computed from the untruncated text. The method is called exactly once per directive.
67. **Evaluation order.** `dst`, `format` and all arguments (including Format receivers, which are copied) are evaluated left to right before anything is written. If a `[]byte` argument, or memory reachable from a Format receiver, aliases `dst`, the output is unspecified.
68. **Totality.** A `%v` directive resolved to a Format method is a call edge from the calling function to that method: it takes part in SCC / mutual-recursion detection exactly like a direct call (a Format method formatting its own type with `%v` is E4002 at the method; `A.Format` <-> `B.Format` is E4004 once, at the first member). A Format method has no unsigned parameter, so it can never carry a valid measure. For loop invariance (decision 54), formatTo writes memory like `copy` into `dst`, and with a Format method it counts as a user call.
69. **Scope.** `dst` is only borrowed; formatTo retains nothing and its result (a byte count) has no origin.
70. **Comptime.** formatTo is supported inside comptime functions with identical semantics (finc0 runs the runtime's `fincrt.Fmt`, finc1 a port of it); every formatted argument costs one unit of fuel, a Format method is interpreted like any other call (one more unit, depth-bounded).
71. **Codegen.** Each call is expanded at compile time into an immediately called Go function literal over `fincrt.Fmt` (docs/runtime_api.md); Go's `fmt` is never used at run time. finc0 and finc1 emit it byte for byte identically.

### Sum types (enums and `match`) — details and grammar in docs/v0_2.md, "Sum types"
72. New code **E2012 NON_EXHAUSTIVE_MATCH**, also used for unreachable match arms. Messages: `non-exhaustive match on T: missing V1, V2` (variants in declaration order, at `match`), `non-exhaustive match expression on T: missing '_' arm` (at `match`), `unreachable match arm: it follows the '_' arm`, `unreachable pattern: variant V is already covered`, `unreachable pattern: duplicate case X`, `unreachable '_' arm: all variants of T are covered` (at the pattern or or-pattern alternative).
73. Exhaustiveness: a `match` on an enum without a `_` arm must name every variant (or-pattern alternatives count). Other scrutinee types (integers, bytes, bool, string): statements need not be exhaustive (Go-like); match expressions need a `_` arm (`true | false` does not count; superseded by 99–100: exhaustiveness is decided by usefulness, `true` and `false` cover bool, tuples must be exhaustive). Coverage is checked only when every pattern is valid. For decision 37 a match on an enum without `_` counts as exhaustive even when E2012 is reported (no cascading E2003).
74. Reachability (E2012): any arm after `_`; a variant named twice (also within one or-pattern, or qualified and unqualified); a constant pattern equal by value to an earlier one (`1 | K` with `K = 1`); `_` after all variants are covered.
75. Or-patterns `P1 | P2 | ...` in statement and expression arms. Alternatives may not be `_` and (superseded by 95) may not bind names other than `_` (E2002); a payload variant is written `V(_, _)`. Alternatives declare no symbols. Codegen: one `case a, b:` list.
76. Unqualified variant patterns: if the scrutinee is an enum, an unqualified pattern name that is one of its variants is that variant, even when a constant of that name is in scope; a constant pattern on an enum scrutinee is E2002 (`constant K cannot be a pattern for enum type T`; superseded by 111: a constant of the enum type whose value is a variant without payload is that variant, other constants are E2002 by assignability). `Type.Variant` stays valid; a generic enum's name qualifies patterns on its instances (`Option.Some(x)` on `Option[u32]`). Patterns of imported enums must be unqualified (`pkg.Type.Variant` is not in the grammar). Construction stays qualified.
77. `match` expressions (a `Primary`; a statement that starts with `match` is still a MatchStmt). Arms are expressions only (no blocks; no-value calls such as `panic(..)` are E2002) separated by newline, `;` or `,`; at least one arm. Arm types: typed arms must be identical (`match arm has type T, want U`, E2002, at the arm); untyped constant arms take the typed arms' type; if all arms are untyped the result is untyped (untyped int and char mix to untyped int) and its context converts every arm (overflow reported per arm). The result is a constant iff the scrutinee is constant and the selected arm is constant, so `const C = match Color.Red { ... }` works. In messages a match expression prints as `match expression` (exprString) or on one line (ast.Format).
78. Scope/linearity: arms of a match expression are branches; payload bindings get the scrutinee's origin and are Borrowed (decision 46); an arm that is a Linear variable moves it (like an assignment's right-hand side); origin(match expr) = join of the arms.
79. Totality: match-expression arms are branches of the flow walker (bindings are fresh). Patterns give no facts: `match n { 0 -> 1; _ -> f(n-1) }` does not prove `n >= 1`; guard with `if n == 0 { return .. }`.
80. Comptime: match expressions and or-patterns are evaluated (first matching arm; no arm is an evaluation error).
81. Compact enum layout: `struct { _tag uint8|uint16|uint32; slots }` (<= 256, <= 65536, more variants). Payload slots are shared by Go type: groups in order of first appearance (variants in declaration order, payloads left to right); a group has as many slots as the most payloads of that type in one variant; a variant's payloads of a type use the group's slots in order. Slot j of a group is `_<key>_<j>`, key = FinCore spelling of a basic type (`u8`, `u32`, `usize`, `int`, `bool`, `string`, `error`, ...), else the Go type if it is an identifier (named types, type parameters, monomorphized names), else the group index in decimal (also when an earlier group already has the key). Constructors set the tag (omitted for variant 0) and their own slots, Go zeroes the rest, so `==` on enums is variant equality. Enums are comparable iff all payload types are.
82. Lowering: `switch x._tag` (a temporary when bindings are used and x is not a local variable); the last arm of an exhaustive match becomes `default`; unused bindings are not emitted. A match expression is an immediately invoked literal `func() T { switch .. { case ..: return arm } }()`, except `return match ...` in a single-result function outside `scope` blocks, which becomes a switch whose arms return (nested `match` arms likewise). A variant construction renders the layout, then the payloads, then the type (this fixes the discovery order of monomorphized instances).
83. Generic enums use Go generics: the layout is computed on the generic declaration (type parameters are slot groups of their own: `Option[T]` has `_T_0`; `Pair[A, B]` keeps `_A_0` and `_B_0` even for `Pair[u32, u32]`). Enums with const parameters are monomorphized and laid out per instance.
84. Enums are Value iff all payloads are Value, may be stored in fixed arrays and structs and are copied by value. An enum containing itself by value (directly, through structs/arrays or generic instances) is E2002 `invalid recursive type E (contains itself by value)`; use an ID into an arena.
85. compiler/: the type checker part for sum types is check_match.fc, the codegen part codegen_enum.fc; 35 Parser methods carry decreases and the Parser SCC has 33 members (new `matchExpr`, `patternAlt`; decision 57). No compliance changes were needed in compiler/ for the feature itself; compiler/ now uses sum types for its own data model: `Val` (comptime values), `TypeRec` (type forms; named-type state in `NamedRec`, type lists interned in a `std/vec.ListArena`, the type table a `std/maps.Table`), `Esc`, `Consume` and `WalkMode`, with 113 matches: the 23 that dispatch over every variant are exhaustive without `_`; the others are payload accessors, single-variant tests and partial dispatches (such as the Code variants of `Val`). Later the checker's assignment context `Ctx` and the call kind `CallKind` (the kind-specific fields of `Call`: callee, method and receiver, builtin and formatTo info, conversion target, variant) became enums too; every pass that dispatches on the kind of a call is an exhaustive match.

### Ergonomics (v0.2) — details in docs/v0_2.md, "Ergonomics"
86. **Auto-& for pointer-receiver calls** (supersedes 10). `x.M(args)`, where `M` has a pointer receiver and `x` is an operand of type `T` (not `*T`), means `(&x).M(args)` if `x` is addressable: a variable (local, parameter, receiver, global, payload binding), a field selector of an addressable struct or through a pointer (`p.f`), an index of an addressable array or of a pointer to an array, an index of a slice, or a pointer dereference `*p` (exactly the operands accepted by an explicit `&`, KindVar). Otherwise E2002 at the selector: `cannot call pointer method M on x (type T): value is not addressable` (call results, struct literals, conversions, constants, match expressions, fields/elements of non-addressable values). Calls through `*T` and value-receiver calls are unchanged. A method value (`x.M` not called) stays E2002 (32). The typed model records `Call.AutoAddr` (finc1: the `autoAddr` payload of `CallKind.Method` / `BuiltinMeth`); `Recv` is `x` and `RecvType` is `*T`, as for an explicit pointer.
87. **Later passes treat the implicit `&` exactly like an explicit one.** Scope: the call's origin is the storage of `x` (as `&x`, decisions 43–45), and the root variable of `x` counts as address-taken; so passing `&local` to a method is fine and storing or returning what the method derives from it is E3002 as before. Linearity: the receiver is a use of `x` (unchanged). Totality: the root variable of `x` is address-taken (unstable for loop invariance and measures, decision 54). Comptime: the receiver is a pointer to the cell of `x`.
88. **Codegen** emits `x.M(args)` (Go takes the address itself; its addressability rules are the same as 86), byte-identically in finc0 and finc1.
89. **Constant strings as `[]byte`.** An untyped string constant (a literal, an untyped constant, a constant expression such as `P + "x"`, parenthesised or not) is assignable to every type whose underlying type is `[]u8` (element exactly `u8`; not `[]T` for a named `T`). This applies in every assignability context: assignment, `var` with a type, call arguments (user functions and methods, builtins such as `bytesEqual` and formatTo's `dst`, capability methods such as `Stdio.WriteStdout`, generic functions and methods after explicit or receiver instantiation, e.g. `id[[]byte]("x")`, `vec.Vec[4, []byte].Push("x")`), `return`, struct literal fields, and the source of `copy` when the destination is a `[]u8`. It does not apply to: typed string constants or values (`strBytes` is still needed: E2002 `cannot use s (type string) as type []u8 in ...`); comparisons (`[]byte` is not comparable, so `b == "x"` stays E2002; use `bytesEqual(b, "x")`); `:=` and untyped `var` (default type `string`); a type parameter type `T` (E2002, as before); package-level `var` initializers (the result is not a constant, decision 27, exactly like `strBytes("..")`); comptime-call arguments (not constants, decision 28).
90. **Semantics of the conversion:** the value is a fresh `[]byte` copy each time the expression is evaluated, exactly `strBytes(e)` (writes never affect a shared static). Typed model: the expression keeps type `string`, kind constant and its value; `Info.ImplicitBytes` (finc1: `nbytes`) marks it. Scope: like `strBytes`, the result has no origin (returning it or storing it anywhere is fine). Comptime: a fresh byte slice, no fuel. Codegen: `[]byte(<constant>)`, where `<constant>` is the usual rendering of the constant (its literal spelling, the constant's name, or the folded literal).
91. **Constant string concatenation** (supersedes the "no string `+`" of 26). `x + y` with both operands constant strings is a constant string (untyped if both are untyped; otherwise the operands' typed type after the usual untyped conversion, and mismatched typed types are E2002 as for every operator). It is usable wherever a constant is: `const` declarations, formatTo formats (`formatTo(b[:], "invalid main signature: %s (" + MainSig + ")", x)`), array lengths via `len`, implicit `[]byte` (89). With a non-constant operand it is E2002 at the operator: `invalid operation: s is not a constant (string concatenation is only allowed for constants)` (the first non-constant operand) — there is no run-time string building. Codegen emits the folded literal (`const Banner = "ergo: start"`).
92. **Comptime and concatenation.** Only true constants are folded: inside a comptime function, parameters and locals are not constants, so `a + b` on string parameters is E2002 like everywhere else, even though the function runs at compile time; `P + "x"` with constant operands is folded by the type checker and costs no fuel.
93. compiler/ still uses only the v0.1/v0.2 forms (`p := &x; p.M()`, `(&x).M()`, `strBytes("...")`) so that older finc0/finc1 can bootstrap it; switching it to the new forms is a separate change.

### Patterns (v0.2) — details and grammar in docs/v0_2.md, "Patterns"
94. **Lexer.** `is` is a keyword (identifiers named `is` were renamed: compiler/main.fc, testdata/pass/pass_std_vec.fc); `..` is a token (`...` unchanged). **AST:** `MatchArm.Guard`, `CtorPattern.Args` (was `Bindings`: `Ident` / `CtorPattern` / `LiteralPattern` / `OrPattern` / `RestPattern`), new `TuplePattern`, `RestPattern`, `TupleExpr`, `IsExpr`; finc1 slots: MatchArm `d` Guard, IsExpr `a` X `b` Pattern, TuplePattern/TupleExpr `l1` Elems.
95. **Binding or-patterns.** Every alternative binds the same names with identical types, else E2002 (`or-pattern alternatives must bind the same variables (x is not bound here)` at the alternative missing x; `(x is not bound in the first alternative)` / `variable x has type T here but U in the first alternative` at the identifier). The resolver declares one symbol per name per arm (pattern); later occurrences refer to it. A name twice in one alternative is E2002 `variable x is bound more than once in a pattern`. An alternative may not be `_` (also in payload or-patterns). Comparisons are made only against a valid first alternative.
96. **Nested patterns.** A payload position holds `_`, a binding, a literal (int, char, string, true/false, nil, `-INT`), a variant pattern (qualified or not) of the payload's type, an or-pattern (`V(1 | 2)`, `V((A | B), x)`), or `..`. A bare payload identifier that names a payload-less variant of the payload's enum is that variant (the resolver still declares the name; it is bound to the payload); otherwise it binds and shadows constants. Constants are patterns only at the top level and in tuple elements; bare top-level/tuple-element names are variants or constants, never bindings. (Superseded by 110–113: one rule for bare names in every position; constants are patterns in payloads too, top-level and tuple-element names bind, and variant names are declared hidden, so they are not bound for the arm.)
97. **Rest pattern.** `..` matches the remaining payloads of a variant pattern, at most once per list (E2002 `at most one '..' is allowed in a payload list`, at the second), in any position; arguments after it count from the end (`payloadIndex`). `V(..)` is valid for every variant; too many fixed arguments is E2003 `variant V has n payload values, pattern binds m`.
98. **Tuple scrutinee.** `match (e1, ..., en)` (n >= 2) evaluates the elements once, left to right; the type is the tuple type `(T1, ..., Tn)` (finc1 `Tuple` TypeRec). Arm patterns are tuple patterns of arity n or `_` (E2003 `tuple pattern has m elements, scrutinee has n`; E2002 for non-tuple/tuple mismatches). A TupleExpr anywhere else (only reachable as `match (a, b) op ...`) is E2002 `tuple (a, b) can only be the scrutinee of a match`.
99. **Usefulness.** Reachability and exhaustiveness use Maranget's algorithm over enum variants, bool true/false, tuple columns, infinite literal domains and `..` (wildcards); guarded arms are checked for reachability but do not cover; fuel 1000 (exhausted: reachable / exhaustive). Unreachable messages, in order: after an unguarded `_` arm (once per arm); `_` (`all variants of T` / `all values of T are covered`); flat variant (`variant V is already covered`); literal/constant (`duplicate case X`); otherwise `unreachable pattern: it is covered by earlier patterns`. Redundant alternatives inside nested or-patterns are not reported.
100. **Exhaustiveness.** Enum and tuple matches must be exhaustive; match expressions on other types too (`missing '_' arm`, unchanged); statements on other types need not. Witness format: `non-exhaustive match on T: missing W1, W2` with witnesses constructor by constructor in declaration order (present constructors specialized; missing ones with `_` payloads combined with default-matrix witnesses; `_` for infinite or constructor-less columns except at the top of a non-tuple scrutinee); tuples print as `(W1, W2)`; a top-level missing variant with all-`_` payloads prints by name (old flat messages unchanged); at most 32, then `, ...`.
101. **Counts as exhaustive** (Info.Exhaustive / finc1 `nexh`, used by terminating statements, ir, linearity and totality flow): unguarded arms exhaustive, or the scrutinee is an enum or tuple; with invalid patterns: enum/tuple or an unguarded `_` arm. A bool statement match with `true` and `false` arms therefore terminates if its arms do.
102. **Guards.** `P if cond -> body` in statement and expression arms; `cond` must be boolean (E2002 `non-boolean guard c in match arm (type T)`); evaluated after the bindings; false falls through to the next arm. Constant match expressions are folded only while every guard on the way is constant.
103. **`is`.** `e is Patterns` is a bool (untyped constant if `e` is constant and the pattern binds nothing), precedence of `<`. ~~Bindings only when the `is` is the if condition or a conjunct of its top-level `&&` chain; elsewhere E2002 `cannot bind x: ...`.~~ Superseded by 118–125: bindings are flow-scoped (any position; visible where definitely matched); the E2002 `cannot bind` message is no longer reachable from `is`.
104. **Simple-statement arm bodies.** In statement matches an arm body may be a simple statement (assignment, inc/dec, call), `return`, `break` or `continue`; the parser wraps it in a Block (no new AST form); `:=` is E1001 `cannot declare variables in a match arm without a block`.
105. **Scope / linearity.** Every binding (nested, or-pattern, `is`) is defined with the origin of its scrutinee (of the matching tuple element) and is Borrowed (46/49); guards and `is` operands are ordinary expressions of the arm's branch / the condition.
106. **Totality.** Guards and `is` are ordinary expressions (calls in them are call-graph edges); arms are branches; patterns give no facts (79).
107. **Comptime.** Tuple scrutinees, nested/or/rest patterns with bindings, guards (after binding) and `is` are evaluated (finc0 `types.MatchValue`, finc1 `imatchPat`).
108. **Lowering.** Flat matches keep the switch lowering (`..` shifts binding slots; the last arm of a match that counts as exhaustive is `default`). Others become an if/else-if chain over temporaries `_fc_tN` (one per tuple element; omitted when all elements are local variables and no arm has a guard; `_ = _fc_tN` when unused): conditions test `_tag` and payload slots along the pattern paths, or-patterns are parenthesized `||` groups; guards reading bindings are `func() bool { x := path; return g }()`; arm bodies start with the bindings they read; binding or-patterns declare `var x T` and assign per alternative; the last arm of an exhaustive match is the final `else`. `is` is an inline test for local variables / single-read patterns, else `func() bool { _fc_tN := e; return test }()`; with bindings the if statement is wrapped in `{ var x T ... }` and the literal assigns them (the wrapping block is superseded by 124).
109. compiler/: the parser gained `scrutinee`, `guard`, `patterns`, `payloadListPush` and `patternAltBody` (40 Parser methods carry decreases; the Parser SCC has 38 members, updating 57/85); the usefulness algorithm is in check_match.fc over LIFO matrix/column stacks and cons-cell witnesses. compiler/ does not use the new pattern features yet.

### Constant patterns and bindings (v0.2) — details in docs/v0_2.md, "Constant patterns and bindings"
110. **One rule for a bare identifier `x` in any pattern position** (top level, tuple element, payload; match arms and `is`), Rust's rule: (a) if the expected type is an enum and `x` is one of its variants, it is that variant; (b) otherwise, if `x` resolves in scope to a constant (a `const` declaration, local or package-level, or a predeclared constant), it is a constant pattern compared with `==`; (c) otherwise it is a fresh binding of the position's type (`_` stays a wildcard). Qualified names: `Q.N` is a variant if `Q` is an enum type, else (`Q` a package) an imported constant; the grammar already allows `pkg.C` in payload positions (`PayloadAlt` includes `VariantPat`). Supersedes the payload rule of 96 and the "no bindings at the top level / in tuple elements" rule of 96/98. **Hazard** (as in Rust): renaming or deleting a constant turns the patterns that name it into bindings (catch-alls); a misspelt constant is a binding too. Later arms then become unreachable (E2012, 114), which catches most cases; in the last arm the change is silent.
111. **Constant patterns.** The resolver records a bare name that resolves to a constant as a use (it is never declared); the type checker gives the constant's value to the pattern. The constant must be assignable to the type of the position (the usual E2002 messages of assignability: `cannot use K (untyped string constant) as type u32`, `cannot use D (type Color) as type u32 in match pattern`); a tuple scrutinee is E2002 `pattern K does not match a tuple scrutinee of type (T1, T2)`; `pkg.K(x)` is E2002 `constant K cannot have bindings` (an unqualified `K(x)` is a variant pattern: E2001 `undefined: K (no constant or variant of T)`). A constant of enum type whose value is a variant **without payload** (`const Def = Color.Red`) is that variant everywhere (usefulness, lowering, comptime, unreachable messages name the variant); a constant whose variant has a payload is E2002 `constant K cannot be a pattern: its variant V has a payload (match the variant instead)`. Supersedes the E2002 of 76 for constants on enum scrutinees.
112. **Top-level and tuple-element bindings.** `x`, `(x, y)`, `(x, 0) | (0, x)`, `n if n > 10 -> ...` bind the scrutinee (element) with its type; the or-pattern rules of 95 apply unchanged (same names with identical types in every alternative; a name twice in one alternative is E2002). A binding of a whole tuple scrutinee is E2002 `cannot bind t to a tuple of type (T1, T2) (use '_' or a tuple pattern)` (tuples have no value representation). Bindings shadow outer variables of the same name (also parameters). Guards see every binding of their arm. In `is` the same rule applies; bindings are flow-scoped (118–125; the E2002 `cannot bind x: ...` of 103 is gone).
113. **Variant names shadow nothing.** A bare pattern name that is the name of a variant of some enum type of the program (the set of all `Variant` names of all loaded packages, computed before binding) and does not resolve to a constant is declared **hidden**: it gets a symbol (so it can still bind if the expected type has no such variant), but the symbol is not inserted into the scope. So a variant pattern never shadows an outer name in its arm, `a is Red && b is Paint(Red)` declares nothing twice, and such a name cannot be referenced in the arm (E2001 `undefined`). This supersedes "the name is still declared and bound to the payload" of 96 for payload variant names.
114. **Usefulness.** Constant patterns are literal patterns of their value (infinite domains, except bool: `true`/`false` constants are the bool constructors, and enum constants their variant). Bindings in every position are wildcards. An unguarded top-level binding arm is a catch-all like `_`: it makes the match count as exhaustive (101) and every later arm is E2012 `unreachable match arm: it follows the catch-all binding x` (once per arm). An alternative that is a top-level binding and matches nothing new is E2012 `unreachable binding x: all variants of T are covered` / `... all values of T are covered`; a repeated top-level constant `unreachable pattern: duplicate case K`; nested constants fall under `it is covered by earlier patterns`. Witnesses are unchanged (constants are never printed).
115. **Lowering, comptime, passes.** Constant patterns become `==` comparisons with the folded constant value (switch case labels in flat matches, `path == value` in if chains; enum constants test `_tag`). A match with a top-level binding (or a bare variant whose hidden symbol is read, which cannot happen in valid code) is lowered as an if chain; bindings are assigned from the scrutinee temporaries (`x := _fc_t0`; or-patterns `var x T` + per-alternative assignment); guards that read them use the function-literal form of 108. Payload constants make a match non-flat and an `is` test non-single-read. Comptime binds top-level and tuple-element bindings (`MatchValue` / `imatchPat`), compares constants by value. Scope/linearity: top-level and tuple-element bindings are defined with the origin of their scrutinee element and are Borrowed (105); totality: they are killed like payload bindings and constants give no facts (79). finc0 helpers: `types.BareName`, `Info.PatBinding`, `Info.IsBindingPat`, `Info.PatConst`; finc1: `bareName`, `patBindSym`, `isBindingPat`, `patConst`, `constPat`, `bindPat`, `catchAll` (check_match.fc), `bPatBare` and `bVariantName` (resolve.fc).
116. **No ambiguity diagnostic.** Under 110 a name that resolves to a constant is never a binding, so the "binding that matches a constant of the same function or package" case cannot arise; the remaining hazard is the silent change of meaning of *existing* payload bindings named like a constant in scope. A one-off finc0 scan (a resolver hook reporting every payload binding whose name resolves to a constant, run over compiler/, std/, testdata/, examples/, scripts/diffcheck|diffbuild/cases and every unit-test snippet that diffcheck/diffbuild extract) found one: `Some(K)` in scripts/diffcheck/cases/patterns_errors.fc, a deliberate test of the old shadowing rule, which now tests a constant payload. No rename was needed. New code is written against the new rule, and E2012 / assignability errors catch most misuses, so no extra diagnostic was added.
117. compiler/ (finc1) implements 110–116 identically (diagnostics and Go output byte for byte); it still uses only forms both compilers at the time of this change support (no constant payload patterns, top-level or tuple-element bindings).
### `is` flow bindings (v0.2) — details in docs/v0_2.md, "Patterns", "Flow-scoped `is` bindings"
118. **Outcome sets** (supersedes the binding restriction of 103 and the "bindings outside binding positions stay E2002" of 112). Top-level bindings (112) take part like payload bindings: `x is n` binds n to x (a tuple cannot be the operand of `is`, 98). Every boolean expression `e` has a true set T(e) and a false set F(e) of `is` bindings, the variables that are definitely matched when `e` evaluates to true / false: `x is P`: T = the bindings of P, F = {}; `!A`: T = F(A), F = T(A); `A && B`: T = T(A) + T(B), F = {}; `A || B`: T = {}, F = F(A) + F(B); `(A)`: those of A; every other expression (comparisons, calls, `x is P` as an operand of `==`, ...): {}, {}. Sets are ordered by source position. ~~`F(A && B)` and `T(A || B)` are always empty (no intersection of names bound on both sides).~~ Superseded by 126: they are intersections by name. An `is` may appear with bindings anywhere; bindings in no visible position, or never used, are not an error.
119. **Visibility.** T(A) is in scope in B of `A && B`; F(A) in B of `A || B` (`!(v is Int(_, l)) || l < 100`); T(cond) in the then block of an `if`, F(cond) in its else branch (also an `else if`, whose condition and blocks see them); T(cond) in the body of a `for` (not in its post statement, decreases clause or after the loop); T(guard) in the body of its match arm (statement block or arm expression; not in other arms). Nowhere else: a use elsewhere is the resolver's E2001 `undefined: x` (or resolves to an outer variable of that name). The resolver creates the symbols of each `is` pattern in a scope of its own (the pattern's names are classified by 110–113 as before: constants compare, a hidden variant-name symbol of 113 takes no part in any outcome set and stays invisible; or-pattern unification as in 95) and inserts them into the scopes of the positions above; finc1 moves a symbol between scopes (a symbol belongs to one scope at a time; the scopes it leaves are closed).
120. **Let-else.** An `if` statement directly in a statement list (block, function body, arm block; not an `else if`) without an else branch declares F(cond) in the enclosing block after the if, exactly like a `:=` at the if statement: a name already declared in that block (for the top level of a function body: also a parameter or receiver) is E2001 `x redeclared in this block` at the binding. This is decided syntactically by the resolver. The type checker then requires the then block not to complete normally where the bindings are used: it must end in a terminating statement under decision 37's rules (return, panic, exhaustive terminating match, if/else both terminating, `for {}` without break, scope/block) extended by `break` and `continue` (recursively, e.g. `if c { break } else { continue }`). Otherwise every use of such a binding after the if is E2002 `cannot use x: the then block of the if statement that binds it can complete normally`; unused bindings are fine (`if !(v is Int(_, l)) { n = 2 }` is valid). `if !(a is X(p)) || !(b is Y(q)) { return }` and `if !(t is Slice(e) && e > 3) { return }` bind p, q and e afterwards.
121. **Duplicates.** A name in both operand sets of a union (T(A) + T(B), F(A) + F(B)) is E2001 `x redeclared in this condition` at the later binding, which is dropped from the set (the earlier one stays visible). Names in different sets or positions follow ordinary scoping: `a is X(p) && !(b is Y(p))` is fine (the second p is in F(B), visible nowhere). A name bound twice in one pattern stays E2002 (95).
122. **Shadowing** follows block scoping: the positions of 119 are nested scopes, so a binding shadows outer variables and an inner `:=` may shadow a binding. The operand of `is` is resolved before its bindings exist: `if !(x is Some(x)) { return }` reads the outer x (in a nested block; at the top level of a function body with a parameter x it is E2001 by 120).
123. **Later passes.** Types come from the payloads (unchanged). Scope/linearity: every binding is defined where its `is` is evaluated, with the origin of the operand, and is Borrowed (105); the let-else needs nothing special since the rest of the block is reached only when the then block was not run. Totality: bindings are fresh variables and patterns give no facts (106); conditions still give their facts, so after `if !(o is Some(k)) || n == 0 { return }` the walker knows `n != 0`. Comptime: `is` defines its bindings in the frame when it matches; reads follow the resolver's scoping.
124. **Lowering.** Before each statement, codegen declares the bindings of every `is` in the statement's own expressions (not in nested blocks or function literals; including the conditions of an else-if chain, a for statement's init, condition and post, match-statement guards and arm expressions, match-expression arms anywhere in them) that are read anywhere: `var _fc_tN_x T` in source pre-order, N a fresh temporary number; the binding's Go name is `_fc_tN_x` everywhere, so hoisted variables never clash with or shadow other Go names. The test assigns them: `func() bool { _fc_tM := e; if test { _fc_tN_x = path; return true }; return false }()`. Short-circuiting `&&`/`||` guarantees that a binding is only read after its test matched. There is no wrapping block (supersedes the `{ var x T ... }` of 108): a let-else's variables stay declared in the enclosing Go block, so `if !(<test>) { return }` is followed by plain reads. Bindings that are never read are neither declared nor assigned (no "declared and not used"); a for condition reassigns its variables in every iteration. finc0 and finc1 emit it byte for byte identically.
125. compiler/: the finc1 resolver gained `bIfStmt`, `bFlow` (outcome sets on a LIFO symbol stack, `MaxFlowSyms = 4096`) and `bVisible`; the checker `markUnbound` (`chkUnbound`) and `terminatingList`/`terminating` with a `jumps` flag; codegen `cgHoistIs`, `cgHoistExpr` and the renaming table `cgSymTmp`. compiler/ does not use flow bindings yet (both current compilers must build it). The resolver declares the bindings of every pattern, so the former E2002 `cannot bind x: an 'is' pattern can bind variables only in the condition of an if statement` is removed (`bindPat` keeps a silent guard for an undeclared name, reachable only when the symbol table is full).

### Assignability follows Go
126. **Assignability** (refines 33, 35, 63, 89, 111; supersedes the former implementation rule "identical underlying types and at least one side not a declared `Named` type", which treated the predeclared basic types as unnamed and so accepted `f(n)` with `n Name` for `type Name u32` / `func f(x u32)`, and a `const F Fmt = "%d"` of `type Fmt string` as a formatTo format; the emitted Go then failed to compile). A value `x` of type `V` is assignable to `T` iff one of: (a) `V` and `T` are identical; (b) `V` and `T` have identical underlying types (not a type parameter or opaque type) and at least one of them is **not named**, where declared types, generic instances, the predeclared named types (`Duration`, capability types, ...) **and the predeclared basic types** (`u8` ... `usize`, `bool`, `string`, `error`) count as named, exactly as in Go; so `Name` and `u32` are not assignable to each other in either direction, while `type Buf []u8` and `[]u8`, or a named func type and an unnamed func type, are; (c) `x` is an untyped constant representable in `T` (unchanged; `const K = 3` and literals still go to `Name`); (d) the nil rules of 33; (e) the FinCore rules: a total func where a driver func of the same parameter and result types is expected (35, under the same named/unnamed condition as (b)), an untyped constant string where an underlying `[]u8` is expected (89/90), and values of error types (`type E error`) assignable to each other (error is an interface in Go). Explicit conversions (`u32(n)`, `Name(x)`, `string(F)`) are unchanged (conversion still allows identical underlying types, integer to integer and pointers with identical underlying base types). The rule is used everywhere assignability is: assignment and `var` with a type, arguments (functions, methods, builtins such as formatTo's format and `strBytes`, capability methods, variant payloads, generic instances after instantiation), `return`, struct literal fields, multi-value assignment, constant patterns (111: `const K Name = 3` is not a pattern on a `u32` scrutinee). Diagnostics are the existing E2002 `cannot use x (type V) as type T in <context>`, identical in finc0 (`types.assignable`, `hasTypeName`) and finc1 (`assignable`, `hasTypeName` in checker.fc). Binary operators, including comparisons, keep requiring identical operand types after untyped conversion (E2002 `mismatched types Name and u32 for operator ==`): stricter than Go's "assignable to each other" only for a named composite type against its unnamed underlying type, so still sound. Slice and array types compare their element types by identity (`[]Name` is neither `[]u32` nor assignable to it; `copy` needs identical element types). No program in compiler/, std/, testdata/, examples/ or the snippet corpora relied on the old rule apart from the formatTo unit test with `const F Fmt` (now an expected E2002; `string(F)` works). Regression check: `make diff-build` reports every case that a compiler accepts but `go build` rejects ("accepted by finc, rejected by go build") as a mismatch instead of "fail in both", and `make diff-build-vet` (`diffbuild -govet`) also runs `go vet` on the emitted Go of every case both compilers build.
### `is` flow intersections (v0.2) — details in docs/v0_2.md, "Flow-scoped `is` bindings"
127. **Intersections** (supersedes "`F(A && B)` and `T(A || B)` are always empty" of 118 and 121). A name is bound in an outcome if it is bound on every path to it: `T(A || B) = T(A) * (F(A) + T(B))`, `F(A && B) = F(A) * (T(A) + F(B))`, where `*` intersects by name; `T(A && B)` and `F(A || B)` stay unions with the E2001 of 121. `!` swaps, parentheses are transparent, and B still sees T(A) (`&&`) / F(A) (`||`). By induction T(e) and F(e) never share a name (an `is` has F = {}; unions and intersections preserve it), so the intersections are `T(A) * T(B)` and `F(A) * F(B)`, which both resolvers compute. A name present on one side only is not bound in that outcome (a later use is E2001 `undefined: x` or the outer variable); this is not an error. The result keeps the order of the left operand (first occurrence). The same name in both operands of an intersection is not a redeclaration; `(a is X(p) || b is Y(p)) && c is Z(p)` still is (the union).
128. **One variable.** The resolver merges the later binding of an intersected name into the earlier one (the left operand's symbol, transitively for chains such as `a is S(x) || (b is S(x) || c is S(x))`) and, after binding all packages, replaces merged symbols by their root in Defs, Uses and function-literal captures (finc0 `binder.intersect` / `applyMerges`, finc1 `bFlowIntersect` / `bApplyMerges`). Every later pass therefore sees one symbol defined by several identifiers, like the alternatives of a binding or-pattern (95). This is sound because the merged bindings are never visible at the same time (the earlier one is in T(A), B sees only F(A)).
129. **Types.** The type checker gives the symbol the type of its first `is`; at a later binding of a merged symbol with a different type it reports E2002 `variable x has type T here but U in the first is test that binds it` at the later identifier (invalid types are not compared).
130. **Passes.** Scope/linearity: each binding identifier defines the one symbol with its operand's origin, so its origin is the join of both operands' origins (the multi-definition join used for assignments and or-patterns) and it is Borrowed; returning it is E3002 if either operand refers to local storage. Totality: bindings are fresh (each `is` kills the variable). Comptime: whichever test matched defines the symbol's cell.
131. **Lowering.** The hoisted `var _fc_tN_x T` (124) is declared once per statement, at the first test that binds the symbol, and every test that binds it assigns the same variable, so whichever path ran it holds the matched value. A merged name that is never read is neither declared nor assigned. finc1 tracks declared symbols per hoisted statement with a generation counter (`cgHoistGen`, `cgSymHoist`); finc0 with a per-statement set. compiler/ does not use intersections (both current compilers must build it).
